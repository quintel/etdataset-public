# Emissions processing pipeline

The `emissions_processing_pipeline.ipynb` fetches GHG emissions data from various sources for all datasets in `input/config_country_datasets.csv` and generates emissions output CSVs for the datasets that will be used in ETSource.

## Processing steps
The pipeline converts raw source data to the final emission CSVs required for the datasets, containing emission data for 1990 and the dataset start year. The pipeline is structured in the following steps:

0. **Configuration**. Package and helper imports, configurations of paths and datasets.
1. **Retrieve and save raw data files**. Fetched emissions data from various sources and exports raw
  source files to source_analyses folder for verification purposes.
2. **Pre-process data and save intermediate files**. Pre-processes GHG emissions data, validation
  saving intermediate files in the data folder.
3. **Map CRT categories to ETM sectors**. Based on `crt_etm_mapping.csv` where conversion is done
  of emissions reported to CRT categories to ETM sectors and subsectors.
4. **Export ETM output CSVs**. Export emissions data categorised to ETM sectors as output CSVs to
  the data folder. These files will be used in ETSource.


## Data source hierarchy

The table below gives an overview of the used data sources including the assigned priority order.

| Priority | Source | Used for country datasets | Notes |
|---|---|---|---|
| 1 | **UNFCCC API** | All country datasets except RS, SG, nl2023, and GB/UKNI | Via `unfccc_di_api.ZenodoReader()`; ISO 3166-1 alpha-3 party codes |
| 2 | **UNFCCC CRT Excel** | Serbia, Singapore, NL 2023 | Emission data downloaded manually from https://unfccc.int/first-biennial-transparency-reports |
| 3 | **National Atmospheric Emissions Inventory** | Northern Ireland | Local emissions source, [downloaded](https://naei.energysecurity.gov.uk/reports/greenhouse-gas-inventories-england-scotland-wales-northern-ireland-1990-2023) and saved in source_analyses folder |

## Additional processing steps
Various additional processing steps are done in step 2.

### Netherlands — Mobile machinery
Emissions from the mobile machinery sub-categories are reallocated to the transport sector, which is in line with how demand for mobile machinery are currentrly modelled in the ETM. The mobile machinery categories are:

| CRF code | Category |
|---|---|
| `1.A.2.g.vii` | Manufacturing industries — Off-road vehicles and other machinery |
| `1.A.4.a.ii` | Commercial/institutional — Off-road vehicles and other machinery |
| `1.A.4.b.ii` | Residential — Off-road vehicles and other machinery |
| `1.A.4.c.ii` | Agriculture — Off-road vehicles and other machinery |
| `1.A.5.b` | Other — Mobile |

### Northern Ireland and Great Britain

Great Britain (GB) emissions are generated by subtracting Northern Ireland (UKNI) emissions from United Kingdom (UK) emissions:

```
GB = UK - UKNI
```

This calculation is performed in section 4.1 of the processing pipeline using the **final `emissions.csv` files** (after CRT→ETM mapping) rather than intermediate files. This approach:

- Performs simple row-by-row subtraction on aligned data
- Merges UK and UKNI on key columns (etm_sector, etm_subsector, use, ghg)
- Subtracts UKNI values from UK values
- Handles LULUCF by attributing negative co2 values to 'removals' and positive values to 'emissions'

**Known limitation**: UK uses 2019 as its analysis year while UKNI uses 2018, creating a year mismatch. GB 2019 emissions are calculated as UK 2019 - UKNI 2018. This is an accepted limitation until UKNI 2019 data becomes available.

### Sweden and Singapore

For Sweden and Singapore, some parent CRT codes do not equal the sum of its child CRT codes. A correction is done so that the difference of the parent code and sum of child codes is allocated to a child code.

#### Sweden (UNFCCC API source)
| Corrected child code(s) | Correction | Reason |
|------|-----------|--------|
| `2.C.1.f` | Residual from `2.C.1` | UNFCCC API children of `2.C.1` do not sum to the parent. The difference is assigned to `2.C.1.f` (Other). |
| `2.C.7` | Residual from `2.C` | After fixing the `2.C.1` subtree, the direct children of `2.C` still do not sum to the parent. The difference is assigned to `2.C.7` (Other). |

#### Singapore (UNFCCC CRT Excel source)

| Corrected child code(s) | Correction | Reason |
|------|-----------|--------|
| `2.B.8.b` | Residual from `2.B.8` | - |

### GWP conversion for UNFCCC CRT Excel datasets
For CRT Excel datasets (Serbia, Singapore, nl2023), other GHGs in the detailed energy sector tables are reported in raw kt (not CO2-eq). The pipeline converts these to CO2-eq using **IPCC AR5 GWP100** values.

| Gas | AR5 GWP100 |
|-----|-----------|
| CH4 | **28** |
| N2O | **265** |

Source: [Greenhouse gas emissions in the Netherlands 1990-2023; National Inventory Document 2025 (RIVM)](https://www.rivm.nl/bibliotheek/rapporten/2025-0005.pdf)

Rows where **both** CH₄ and N₂O are flagged as non-occurring ("NO") in the CRT file will still show `NaN` in the Other GHG column.

## Other notes

- Singapore 1990 emissions data is based on 2000 emissions data as this is the
  earliest available emission data in CRT categorisation.
- EU27_european_union_27_countries (2019) uses UNFCCC API party code `EUA`. This represents
  the EU's own UNFCCC submission, which covers the post-Brexit EU27 composition (Croatia in, UK out). This is in line with how the EU27 dataset is defined in the ETM.
- The emissions.csv file for Great Britain 2019 is determined based on UK 2019 minus Northern Ireland 2018. The source file used for Northern Ireland also contains emission data for England, Wales and Scotland for 2019. A future improvement is to generate the Great Britain emission data based on the same source file instead of the current subtraction approach.
- Due to how energy balance flows are modelled in the ETM, reallocation of several CRT categories to ETM sectors were necessary:

| CRT category | Allocated to ETM sector | Comment |
| ------------ | ----------------------- | ------- |
| 1.A.4.c.iii Fishing | Transport | Category entirely excluded from NL datasets as the fishing sector is not modelled for these datasets |
| 1.A.3.e Other transportation | Other | |
